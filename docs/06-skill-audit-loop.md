# Петля аудита скилла: аудит → патч → повторный аудит → аудит аудита

Скилл `dsh-orchestration` (см. [skill/dsh-orchestration.SKILL.md](../skill/dsh-orchestration.SKILL.md))
сам прошёл через дисциплину, которую предписывает. Ниже — хронология петли и итоговые
вердикты. Исполнитель аудитов — DeepSeek Harness (headless-режим) с доступом к
первоисточникам через инструменты; проверка его отчётов — независимая сверка каждой
цитаты аудитором (мной).

## Раунд 1: аудит скилла против первоисточников

**Вход:** скилл v1 (102 строки) + четыре первоисточника: `orchestrator.py` (2879 строк),
`orchestrator.toml` (664 строки), доктрина фактической точности (173 строки),
скилл-диспетчер оркестратора.

**Задание:** проверить каждое утверждение скилла о механизмах оркестратора
(CONFIRMED / DISTORTED / FABRICATED с file:line-доказательством), найти пропущенные
механизмы, проверить корректность адаптации «безинструментный воркер vs dsh с
инструментами».

**Результат:** вердикт **accept-with-gaps**.

- Fidelity: **12/12 механизмов CONFIRMED, 0 FABRICATED, 0 DISTORTED** — все guard'ы,
  BUDGET GUARD, strict review, инцидент фабрикации `cargo test`, эмпирика 84КБ
  найдены в коде со ссылками на строки.
- Найденные пробелы (все подтверждены при проверке аудита):
  - **M1** — отсутствовал фидбек-цикл «отклонение → причина в следующую попытку → лимит»;
  - **M2/M3** — не было seed-дисциплины («дорабатывать зелёное дерево») и сквозной
    памяти по topic-слагам;
  - **M4** — пустой результат: провал есть, но без следствия «не приодевать в
    правдоподобную историю отказа»;
  - **M5** — **гейт необратимых действий отсутствовал целиком** (признан самым
    значимым: dsh умеет удалять/перезаписывать);
  - **M6** — provenance-правило передавало только половину guard'а: без «не вводи
    факты, которых нет в принятых результатах» и без проверки выживания дословных
    доказательств при редактировании;
  - **Q4.1** — эмпирика «84КБ / 10 из 10» приведена без атрибуции: цифра измерена
    на воркере LangGraph и прослеживается только до скилла-диспетчера; в
    orchestrator.toml смежный эпизод записан как «5 прогонов подряд». Ирония:
    антигалюцинационный скилл нарушил собственное provenance-правило.
  - **Q4.4/Q4.6** — BUDGET GUARD не назван по имени; маркер TRUNCATED подавался как
    сигнал dsh, хотя это сигнал из плейбука LangGraph.

**Проверка аудита (аудит аудита):** 14 выборочных цитат из категорий повышенного
риска перепроверены чтением строк — все воспроизведены точно (включая docstring о
поимке фабрикации `cargo test`, `MAX_ATTEMPTS = 2`, «safety net» проверки выживания
доказательств); заявление «у воркера нет инструментов» подтверждено grep'ом
(`bind_tools` — 0 вхождений; worker_llm — голый `ChatOpenAI`). **Аудит принят:
фабрикаций нет, находки валидны.**

## Раунд 2: повторный аудит патча

**Вход:** скилл v2 + отчёт раунда 1 как ground truth по пробелам + первоисточники
для проверки новых утверждений.

**Результат:** вердикт **patch-accepted**.

- Закрытие: **8/8 CLOSED, 0 PARTIAL** (M1–M6, Q4.1, Q4.4, Q4.6) — с номерами строк
  патча и доказательствами из источников.
- Новые утверждения патча: **9/9 CONFIRMED, 0 FABRICATED** (~60k-потолок,
  MAX_ATTEMPTS=2, ссылки B3/C8, «5 прогонов», запись диспетчера, seed/фидбек-пункты,
  topic-memory, TRUNCATED-негатив). Примечательно: аудитор распознал, что «2–3
  попытки» — собственный дефолт скилла для dsh, а не цифра источника, и проверил
  реальные константы; нашёл, что «публикация вовне» не входит в букву B3, но
  обоснована human-gated-публикацией в промпте воркера.
- Регрессии: **0** — нумерация, кросс-ссылки и связность целы.
- Графа «Empiria hygiene»: **PASS** — скилл теперь соблюдает provenance-дисциплину,
  которую преподаёт.

**Проверка повторного аудита:** непроверенные ранее ссылки сверены чтением
(`output/<slug>/<topic>/` в скилле-диспетчере; `memory/<slug>/subtasks/<topic>.md` —
«грузится работнику следующего прогона» — в его runbook'е; все пять диапазонов строк
патча). Итоговый ответ исполнителя верен своему отчёту-артефакту. **Принят.**

## Почему это работает

Петля симметрична и не требует доверия ни на одном шаге:

1. Исполнитель не «слушает» оркестратора — он читает первоисточники инструментами
   и цитирует строки.
2. Оркестратор не «верит» исполнителю — каждая цитата воспроизводится независимо.
3. Прошлый отчёт исполнителя становится ground truth следующего раунда —
   самосогласованность проверяется механически, а не на слово.

Обе стороны поймали реальные дефекты: исполнитель — пять пробелов и нарушение
provenance в скилле оркестратора; оркестратор убедился в отсутствии фабрикаций
в обоих отчётах исполнителя.
