# Методология аудита ответов исполнителя

Основа — правило, выведенное из реальных инцидентов (наблюдались воркеры,
выдумывавшие вывод `cargo test`): **отчёт исполнителя об успехе — заявление,
требующее верификации, а не факт.** Ниже — приёмы, собранные в работающий протокол.

## Четыре guard'а (по мотивам guard'ов промышленного Python-оркестратора)

| Guard | Где применяется | Суть |
|---|---|---|
| **No-fabrication** | текст задачи (integrity-блок) | Запрет утверждать «запускал/проверил» без исполнения; запрет выдуманных API/флагов/пакетов; пробел в данных — явное «не хватает X», а не правдоподобный текст |
| **Review-verification** | приёмка результата | Доказательство — только вывод, захваченный реальным исполнением; уверенная проза модели — не证据. Если критерий требует «протестированного кода», а проверяемого вывода нет — критерий не выполнен, «насколько бы уверенно ни звучал текст» |
| **Collect-contradiction** | выбор из кандидатов | Кандидаты расходятся в факте или числе — показать расхождение явно, не выбирать молча и не усреднять |
| **Synthesis-provenance** | итоговый ответ | Ни одного нового факта вне принятых результатов; конфликты surfaced; происхождение каждой части размечено |

## Протокол приёмки (исполнение — обязательное)

1. **Независимый перезапуск.** Тесты/сборку аудитор гоняет сам, в чистом процессе;
   файлы читает сам. Отчёт исполнителя «OK» не принимается как доказательство.
2. **Дифференциальное тестирование** для алгоритмики. Эталонная реализация
   (stdlib / brute force / простая структура) + 10–20 тыс. случайных операций:
   расхождение = reject с номером операции.
3. **Инварианты.** Контракт проверяется на границах: размер/ёмкость, валидация
   входов, отказ на недопустимых значениях.
4. **Полнота артефакта.** Файл заканчивается корректно (не обрывается), нет
   маркеров обрезки; пустой ответ — провал, а не «наверное ничего не нужно».
5. **Adversarial-кейсы, которых не было в задаче.** Граничные значения и входы,
   которые исполнитель не мог «подогнать» под известные ему критерии.
6. **Сверка цитат.** Каждая цитата «реального вывода» в ответе исполнителя
   воспроизводится аудитором: версия инструмента, текст ошибки, списки имён —
   символ в символ. Правдоподобный, но фиктивный вывод — главный признак
   фабрикации.
7. **Лимит попыток.** После исчерпания — явный отказ «проверенный результат
   получить не удалось», а не правдоподобная заглушка.

## Provenance в финальном ответе пользователю

Итоговая сводка обязана разделять:

- что сделал исполнитель;
- что перепроверено аудитором независимо (и как);
- что передано как есть (непроверенное), с явной пометкой.

Непроверенные фрагменты не сливаются с проверенными в один уверенный текст.
Найденные **границы** (что вне контракта задачи) документируются явно — например,
«slugify ASCII-only: кириллица схлопывается в пустую строку» — вместо молчаливого
«работает для всего».

## Классификатор находок аудита

| Находка | Вердикт |
|---|---|
| Все критерии исполнены, цитаты воспроизведены, adversarial-кейсы проходят | **Accepted** (+ задокументированные границы) |
| Цитаты правдоподобны, но не воспроизводятся | **Rejected: fabrication** |
| Тесты проходят у исполнителя, но не в чистом процессе | **Rejected: environment-dependent** |
| Артефакт обрывается / маркеры обрезки | **Rejected: truncated** (требовать дифф вместо переиздания) |
| Критерии формально исполнены, но контракт подменён | **Rejected: contract drift** |
