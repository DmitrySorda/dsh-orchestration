# dsh-orchestration — оркестрация DeepSeek Harness с независимым аудитом

Практический опыт установки, настройки и использования [DeepSeek Harness (dsh)](https://github.com/deepseek-ai/deepseek-harness) в роли **исполнителя** под управлением внешнего агента-оркестратора: постановка задач, приём и независимая верификация ответов, дисциплина против галлюцинаций.

> Формула проекта dsh: `Agent = Model + Harness`, философия — «Everything is a Plugin».
> Формула этого репозитория: **оркестратор не генерирует — оркестратор ставит задачи и аудитирует**.

## Ключевые результаты

1. **Установлен и доведён до рабочего состояния dsh 0.1.1-rc.2** с Web UI и набором лучших плагинов экосистемы. Обнаружено и задокументировано несовпадение линеек версий dsh ↔ плагинов (0.1.2-rc.1 ломает загрузку популярных плагинов).
2. **Отработан паттерн оркестрации**: `dsh --profile headless "<задача с критериями приёмки>"` — генерацию выполняет DeepSeek, оркестратор только формулирует и проверяет.
3. **Сформулирован и эмпирически проверен антигалюцинационный контракт**: integrity-блок в тексте задачи + независимый аудит каждой цитаты и каждого отчёта «тесты прошли». На ловушке с несуществующим классом `collections.OrderedCounter` исполнитель корректно признал отсутствие API и привёл проверяемый дословный вывод.

## Принципы, которые здесь исповедуются

- **Отчёт исполнителя — заявление, требующее верификации, а не факт.** Единственное доказательство — независимый перезапуск в чистом процессе.
- **Ground truth дословно.** Эталоны и контракты передаются содержимым файла, а не пересказом в тексте задачи.
- **Провал — явно.** После исчерпания попыток сообщается о невозможности получить проверенный результат, а не подставляется правдоподобная заглушка.
- **Provenance.** В итоговом ответе размечено, что сделал исполнитель, что проверено независимо, а что передано как есть.

## Статус совместимости

Проверено на dsh **0.1.2-rc.1** (последняя на момент опыта) и **0.1.1-rc.2** (рабочая). Проект в developer preview — ожидаются ломающие изменения; детали в [docs/01-installation.md](docs/01-installation.md).
